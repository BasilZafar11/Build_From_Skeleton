# Build From Skeleton

Learn to build complete projects by implementing the logic yourself.

Build From Skeleton provides project structure, function signatures, clear
requirements, and tests. You turn the unfinished functions into a working
application, one milestone at a time.

## Who this is for

You know basic programming syntax and want practice connecting functions into a
complete application. The structure helps you get started; the implementation
decisions and debugging remain yours.

Python is the initial focus. Additional languages can be proposed once the first
projects establish a format maintainers can support.

## How learning will work

1. Fork this repository and clone your fork.
2. Pick a published project and follow its own setup instructions.
3. Read the requirements and implement the functions for the first milestone.
4. Run that milestone's tests, then continue through the remaining milestones.
5. Consult optional hints or the separately marked reference solution when needed.

Unfinished Python functions will raise `NotImplementedError`. Learner tests are
expected to fail until you implement the corresponding behavior. Setup and test
discovery should still work in an untouched skeleton.

Each project will have independent dependencies and commands. No virtual
environment is included in a checkout; create one using the project's instructions.

## Contribute to the collection

Contributions can add project skeletons, improve instructions and hints, or fix
tests. **Keep learner exercises unfinished in contributed skeletons.** Complete
your own solutions in your fork; reference solutions belong in a separate,
clearly marked location.

- Read [CONTRIBUTING.md](CONTRIBUTING.md) before opening a PR.
- Follow the [skeleton standard](docs/skeleton-standard.md).
- Propose substantial new projects through a
  [new skeleton issue](https://github.com/BasilZafar11/Build_From_Skeleton/issues/new?template=new-skeleton.yml).
- Read the [code of conduct](CODE_OF_CONDUCT.md).

Maintained by [Basil Zafar](https://github.com/BasilZafar11). Review happens as
maintainer time permits; there is no guaranteed response time.
